# 마음자로(가칭) 미니멀 마인드 컨트롤 앱
## 제품·UX·기술 구현 계획서 / PRD v3.0

- 작성일: 2026-09-04
- 문서 상태: MVP 개발 기준안
- 프로젝트 성격: 식욕 충동 순간에 짧은 가상 주입 의식을 실행하고, 사용 패턴을 기록하는 웰니스·자기조절 앱
- 핵심 플랫폼: iOS·Android 스마트폰 및 홈 화면 위젯

> **제품 핵심 문장**  
> 먹고 싶은 순간, 홈 화면 위젯을 누르고 스마트폰을 배에 댄 채 가상 주입을 완료함으로써 충동과 행동 사이에 짧은 심리적 전환점을 만드는 앱.

# 1. 제품 개요

## 1.1 해결하려는 문제

먹고 싶은 충동은 길게 고민한 뒤 발생하기보다 특정 음식 노출, 습관, 스트레스, 심심함 또는 피로에 의해 순간적으로 발생하는 경우가 많다. 기존 식단·칼로리·체중 기록 앱은 사용자가 이미 먹은 뒤 기록하거나 여러 정보를 입력해야 하므로, 충동이 발생한 바로 그 순간에 개입하기 어렵다.

이 앱은 사용자가 홈 화면에서 한 번에 진입하여 몇 초 안에 다음 행동을 완료하도록 한다.

```text
식욕 충동 발생
      ↓
홈 화면 위젯에서 강도 확인 또는 변경
      ↓
위젯의 주입 버튼 탭
      ↓
가상 주사기 화면 즉시 실행
      ↓
스마트폰을 배에 대고 화면을 길게 누름
      ↓
액체 감소 + 햅틱 + 가상 주입 애니메이션
      ↓
선택한 강도와 마인드 컨트롤 문구 표시
      ↓
사용 시간·강도 자동 기록
```

## 1.2 제품의 본질

이 앱의 본질은 마운자로나 다른 의약품을 모방하거나 대체하는 것이 아니다. 주사기 형태는 사용자가 자기조절 상태로 전환하는 **시각적·촉각적 의식(ritual)**이다.

제품의 목표는 다음과 같다.

- 식욕을 의학적으로 억제하거나 치료한다고 주장하지 않는다.
- 욕구가 생긴 순간 자동 행동으로 이어지기 전에 짧게 멈추게 한다.
- 매번 복잡한 기록을 요구하지 않고, 사용 시각과 선택 강도를 자동 저장한다.
- 장기적으로 사용자가 자신이 어느 요일과 시간대에 앱을 자주 찾는지 확인하게 한다.

## 1.3 제품 포지셔닝

### 권장 정의

> **식욕 충동 순간에 사용하는 미니멀 자기조절 의식 및 패턴 기록 앱**

### 권장 스토어 설명

> 먹고 싶은 순간, 위젯을 누르고 짧은 가상 주입 의식을 실행해 보세요. 선택한 마인드 강도와 사용 시각이 자동으로 기록되어, 내가 언제 마음자로를 자주 찾는지 확인할 수 있습니다.

### 사용하지 않을 정의

- 비만 치료 앱
- 식욕억제제 대체 앱
- 마운자로와 같은 효과를 내는 앱
- 가상 약물 투여 앱
- 약물 용량 계산기

# 2. 핵심 제품 원칙

## 2.1 즉시성

위젯을 탭한 뒤 주입 화면이 열리기까지 중간 홈 화면, 광고, 로그인, 질문 또는 팝업을 두지 않는다.

## 2.2 최소 입력

주입 전에 선택하는 값은 **강도 1~5**뿐이다. 강도는 기본값을 저장하고 위젯에서 미리 바꿀 수 있으므로, 실제 충동 발생 시에는 주입 버튼 한 번만 눌러도 된다.

## 2.3 짧고 완결된 의식

전체 핵심 경험은 약 3~6초 안에 끝난다. 타이머, 호흡 세션, 설문, 음식 입력, 칼로리 입력을 넣지 않는다.

## 2.4 비의료적 표현

- `mg`, 투여 권장량, 효과 지속 시간, 약물명은 사용하지 않는다.
- 강도는 의약품 용량이 아니라 애니메이션·햅틱·문구 톤을 결정하는 앱 내부의 자기조절 강도다.
- 완료 문구는 실제 생리적 변화나 식욕 감소를 단정하지 않는다.

## 2.5 사실 기반 데이터

후속 질문이 없는 현재 UX에서는 실제로 음식을 참았는지 알 수 없다. 따라서 다음 항목만 보여준다.

- 마음자로 실행 횟수
- 일별 누적 강도
- 시간대별 실행 빈도
- 요일별 실행 빈도
- 강도별 사용 분포

다음 항목은 표시하지 않는다.

- 참기 성공률
- 식욕 감소율
- 체중 감량 기여도
- 실제 포만감 변화

## 2.6 로컬 우선

MVP는 회원가입과 서버 없이 작동한다. 모든 기록은 사용자의 기기에 저장한다.

# 3. 목표 사용자와 사용 상황

## 3.1 핵심 사용자

- 식사 사이에 간식이나 야식을 충동적으로 찾는 사람
- 다이어트 앱의 복잡한 입력을 부담스러워하는 사람
- 음식 충동이 발생하는 시간 패턴을 알아보고 싶은 사람
- 짧은 햅틱·애니메이션 의식을 통해 마음을 전환하는 경험을 선호하는 사람

## 3.2 대표 사용 상황

### 상황 A: 야식 충동

```text
22:18 치킨이 먹고 싶어짐
→ 홈 화면 위젯에서 현재 강도 4 확인
→ 주입 버튼 탭
→ 배에 스마트폰을 대고 화면을 길게 누름
→ 강도 4 주입 완료 + 문구 확인
→ 22:18, 강도 4 자동 기록
```

### 상황 B: 업무 중 간식 충동

```text
15:26 과자가 당김
→ 위젯의 강도를 2로 낮춤
→ 주입 버튼 탭
→ 짧은 주입 완료
→ 15:26, 강도 2 자동 기록
```

### 상황 C: 기록 확인

```text
주말에 앱 아이콘으로 일반 실행
→ 지난 16주 기여도형 히트맵 확인
→ 토요일과 밤 9~11시 사용이 많다는 패턴 확인
```

```text
[홈 화면 위젯]
       ↓

       ↓

[앱 아이콘 일반 실행]
       ↓
[대시보드]
 ├─ 오늘 기록
 ├─ 기여도 히트맵
 ├─ 시간대 패턴
 └─ 설정
```

## 5.2 앱 내 기본 내비게이션

MVP에서는 하단 탭을 2개만 사용한다.

```text
[기록]  [설정]
```

- `기록`: 오늘 요약, 기여도형 히트맵, 패턴 차트, 최근 실행 내역
- `설정`: 기본 강도, 햅틱·사운드, 문구 톤, 데이터 관리, 면책 안내

주입은 탭으로 넣지 않고 대시보드 상단의 주입 버튼 또는 위젯으로 진입한다.

# 7. 위젯 상세 설계

## 7.1 위젯의 역할

위젯은 단순한 요약 화면이 아니라 앱의 **주 인터페이스**다.

```text
Widget = 강도 설정 + 주입 진입
App = 주입 애니메이션 + 기록 확인 + 설정
```

## 7.2 기본 위젯 크기

### 소형 위젯

```text
┌───────────────┐
│ 마음 강도  3  │
│               │
│      ▌│       │
│    마음자로    │
│               │
│    −      +   │
└───────────────┘
```

- 중앙 주사기 또는 `마음자로` 영역: 앱의 주입 화면 실행
- `−`: 강도 1단계 감소
- `+`: 강도 1단계 증가
- 강도 범위: 1~5
- 1에서 `−`, 5에서 `+`는 비활성화

### 중형 위젯

```text
┌────────────────────────────┐
│ 오늘 3회          누적 10  │
│                            │
│ 마인드 강도                │
│ [1] [2] [●3] [4] [5]       │
│                            │
│       [ 마음자로 주입 ]     │
└────────────────────────────┘
```

- 강도 1~5를 직접 선택
- 큰 주입 버튼으로 앱 실행
- 오늘 실행 횟수와 누적 강도를 작은 정보로 표시

## 7.3 위젯 상태 규칙

- 강도는 전역 기본값으로 저장한다.
- 위젯에서 변경하면 앱과 다른 위젯에 즉시 반영한다.
- 앱 실행 시 딥링크에 표시된 캐시값이 아니라 공유 저장소의 최신 강도를 읽는다.
- 강도 변경과 앱 실행이 연속해서 발생하더라도 최신 강도를 사용한다.

## 7.4 플랫폼별 구현

### iOS

- WidgetKit
- App Intents 기반 인터랙티브 버튼
- App Group `UserDefaults`에 현재 강도와 오늘 요약 저장
- 위젯 중앙 버튼은 특정 주입 화면을 여는 App Intent 또는 딥링크 실행
- 인터랙티브 위젯을 위해 iOS 17 이상을 기본 지원 범위로 권장

### Android

- Jetpack Glance
- `actionRunCallback`으로 강도 변경
- `actionStartActivity`로 주입 화면 실행
- DataStore 또는 위젯 상태 저장소에 현재 강도 저장
- 강도 값을 Intent extra로 전달하되 앱 시작 시 공유 상태를 다시 확인

## 7.5 위젯 성능 기준

- 강도 버튼 탭 후 500ms 이내 시각적 상태 갱신을 목표로 한다.
- 위젯에서 주입 화면이 열리는 시간은 웜 스타트 1.5초 이내, 콜드 스타트 3초 이내를 목표로 한다.
- 네트워크 요청 없이 작동한다.

# 8. 강도 시스템

## 8.1 강도 정의

강도는 약물 용량이 아니라 다음 네 요소를 묶은 앱 내부 설정이다.

1. 주사기 내부에 처음 표시되는 액체량
2. 주입 애니메이션 길이
3. 햅틱의 횟수와 밀도
4. 완료 문구의 말투

## 8.2 강도별 동작

| 강도 | 초기 액체량 | 애니메이션 목표 시간 | 햅틱 | 문구 톤 |
|---:|---:|---:|---|---|
| 1 | 20% | 1.2초 | 1회, 부드럽게 | 가장 부드러움 |
| 2 | 40% | 1.5초 | 2회 | 부드러움 |
| 3 | 60% | 1.8초 | 3회 | 중립적 |
| 4 | 80% | 2.2초 | 4회 | 단호함 |
| 5 | 100% | 2.6초 | 5회, 점진적 | 가장 단호함 |

이 수치는 초기 프로토타입 기준이며, 실제 기기 테스트에서 촉감과 피로도를 보고 조정한다.

## 8.3 표시 문구

권장:

- `마인드 강도 3`
- `강도 4 주입 완료`
- `오늘 누적 강도 11`

비권장:

- `7.5mg`
- `고용량 투여`
- `식욕 억제 용량`
- `권장 용량`

## 8.4 강도 선택 UX

- 기본 강도는 3
- 위젯에서 1~5 직접 선택 또는 ± 조절
- 앱 설정에서도 변경 가능
- 앱은 특정 강도를 추천하지 않는다.
- 사용 빈도나 체중에 따라 자동으로 강도를 올리지 않는다.


## 9.2 배 접촉 처리

앱은 스마트폰이 실제로 배에 닿았는지 감지하지 않는다.

- 카메라, 근접 센서, 마이크, 압력 센서를 사용하지 않는다.
- `배에 대고`는 의식을 위한 안내 문구다.
- 사용자가 화면을 길게 누르는 행동만 감지한다.

## 9.3 입력 방식

- 주사기 객체 또는 화면 하단의 넓은 영역을 길게 누른다.
- 터치 다운 후 100~150ms 안에 애니메이션과 햅틱을 시작한다.
- 누르는 동안만 주입이 진행된다.
- 중간에 손을 떼면 애니메이션을 일시 정지하고 `계속 눌러주세요`를 표시한다.
- 다시 누르면 이어서 진행한다.
- 완료 전에 앱이 백그라운드로 가면 기록을 생성하지 않는다.

## 9.4 애니메이션 단계

```text
READY
  ↓ 화면 누름
PRESSING
  ↓
INJECTING
  ├─ 액체 높이 감소
  ├─ 작은 기포 또는 빛 이동
  ├─ 플런저 이동
  └─ 햅틱 동기화
  ↓
COMPLETED
  ├─ 액체 0%
  ├─ 짧은 완료 햅틱
  └─ 완료 화면 전환
```

## 9.5 애니메이션 에셋 구조

강도에 따라 액체량이 달라져야 하므로 단일 MP4나 GIF보다 레이어 기반 에셋을 권장한다.

### 권장 레이어

1. 주사기 외곽 몸체
2. 투명 챔버
3. 액체 레이어
4. 액체 마스크
5. 플런저 또는 내부 이동 부품
6. 반사광
7. 완료 체크 효과

### 권장 구현

- Rive State Machine 또는 네이티브 벡터·마스크 애니메이션
- 입력값: `intensity 1...5`, `isPressing`, `progress 0...1`
- 앱 코드가 progress를 제어하고 햅틱 임계점과 동기화

### 에셋 제작 원칙

- 닥터나우 원본 이미지, 코드, SVG, WebP 또는 화면 녹화를 사용하지 않는다.
- 별도 제작한 일반적 세로형 주사펜 이미지를 사용한다.
- 닥터나우의 구체적인 비율, 라벨, 색 배치, 로고, 카피를 그대로 재현하지 않는다.
- 실제 의약품 제조사 로고나 식별 가능한 펜 디자인을 넣지 않는다.

## 9.6 햅틱 설계

햅틱은 배에 스마트폰을 댄 상태에서 가상 주입감을 만드는 핵심 요소다.

- 시작: 짧은 단일 탭
- 진행: 액체 감소율에 맞춘 부드러운 펄스
- 완료: 조금 더 분명한 완료 탭
- 설정에서 완전 비활성화 가능
- Android 기기별 진동 성능 차이를 고려하여 기본 진동 fallback 제공

## 9.7 사운드

MVP에서는 기본 OFF를 권장한다.

- 조용한 환경에서 사용할 가능성이 높음
- 작은 액체 이동음 또는 완료음만 선택 제공
- 무음이어도 시각·햅틱만으로 모든 상태를 이해할 수 있어야 함

# 10. 완료 화면과 마인드 컨트롤 문구

## 10.1 완료 화면

```text
┌─────────────────────────┐
│                         │
│            ✓            │
│                         │
│       강도 4 주입 완료    │
│                         │
│  지금의 식욕은 신호일 뿐, │
│  반드시 따라야 할 명령은  │
│  아닙니다.                │
│                         │
│       22:18 자동 기록     │
│                         │
└─────────────────────────┘
```

핵심 흐름은 여기서 끝난다. 타이머, 추가 질문, 성공 버튼을 붙이지 않는다.

모바일 OS상 앱을 강제로 자동 종료하는 방식은 권장하지 않는다. 완료 화면을 유지하고 사용자가 홈으로 나가거나, 일반 앱 진입 시에는 화면을 탭해 기록 화면으로 돌아갈 수 있게 한다.

## 10.2 문구 콘텐츠 원칙

- 식욕을 생리적으로 줄였다고 단정하지 않는다.
- 사용자에게 수치심이나 죄책감을 주지 않는다.
- `실패`, `의지가 약하다`, `먹으면 안 된다` 같은 표현을 피한다.
- 욕구와 행동을 분리하고 선택권을 강조한다.
- 2줄 이내, 약 18~45자 분량을 권장한다.
- 최근 10개 문구와 중복되지 않도록 한다.

## 10.3 문구 카테고리

### A. 욕구와 행동의 분리

1. 지금의 식욕은 신호일 뿐, 반드시 따라야 할 명령은 아닙니다.
2. 먹고 싶다는 생각과 먹는 행동은 서로 다른 선택입니다.
3. 욕구가 떠올랐지만, 결정은 아직 당신에게 있습니다.
4. 생각은 왔어도 행동은 스스로 고를 수 있습니다.
5. 지금 멈춘 순간, 자동 반응에서 한 걸음 벗어났습니다.

### B. 충동의 일시성

1. 지금의 당김은 계속 같은 강도로 머물지 않습니다.
2. 욕구는 올라오지만, 그대로 머물지는 않습니다.
3. 이 감각은 잠시 머물다 지나갈 수 있습니다.
4. 지금 느끼는 강도가 곧 영원한 선택은 아닙니다.
5. 잠깐의 파도가 지나갈 시간을 만들어보세요.

### C. 자기결정권

1. 결정권은 식욕이 아니라 당신에게 있습니다.
2. 지금 무엇을 할지는 여전히 당신이 정합니다.
3. 방금 당신은 충동보다 선택을 먼저 꺼냈습니다.
4. 한 번 멈춘 것만으로도 선택할 공간이 생겼습니다.
5. 원하는 것과 필요한 것을 구분할 시간은 충분합니다.

### D. 주의 전환

1. 음식에서 시선을 떼고, 하던 일로 돌아가 보세요.
2. 지금 가장 먼저 하려던 일을 다시 떠올려보세요.
3. 몸을 한 번 움직이고 생각의 방향을 바꿔보세요.
4. 화면을 닫고 주변의 다른 감각에 주의를 돌려보세요.
5. 지금의 생각에 머물지 말고 다음 행동 하나를 정해보세요.

### E. 비판하지 않는 태도

1. 욕구가 생긴 것은 실패가 아닙니다. 반응은 선택할 수 있습니다.
2. 먹고 싶은 마음을 탓하지 않아도 됩니다.
3. 지금의 욕구를 알아차린 것만으로도 충분한 시작입니다.
4. 참아야 한다고 몰아붙이지 말고, 선택을 잠시 미뤄보세요.
5. 자신을 비난하지 않고 다음 행동을 정해보세요.

## 10.4 강도와 문구 톤 연결

| 강도 | 문구 구성 |
|---:|---|
| 1 | 부드러운 인지·수용 문구 중심 |
| 2 | 부드러운 인지 + 가벼운 전환 |
| 3 | 모든 카테고리 균형 |
| 4 | 선택권·행동 분리 문구 비중 확대 |
| 5 | 단호하지만 공격적이지 않은 문구 중심 |

## 10.5 문구 선택 알고리즘

```text
1. 현재 강도에 맞는 톤 후보 필터링
2. 최근 10회 표시 문구 제외
3. 특정 카테고리가 연속 2회 이상 나오지 않도록 조정
4. 후보 중 무작위 선택
5. phrase_id를 이벤트 기록에 저장
```

초기 문구 풀은 최소 100개를 권장한다. 앱 업데이트로 문구를 추가할 수 있으나, 서버 없이 앱 번들에 포함한다.

# 12. GitHub Contribution 형태의 가시화

## 12.1 목적

사용자가 하루에 몇 번 마음자로를 사용했는지 장기간 한눈에 확인하게 한다. GitHub의 Contribution Calendar처럼 날짜별 사각 셀과 농도를 사용하되, 앱 고유의 색상·간격·타이포그래피로 설계한다.

## 12.2 기본 구조

- 열: 주(week)
- 행: 월요일~일요일
- 각 셀: 하루
- 진한 농도: 실행 횟수 또는 누적 강도가 큼
- 대시보드: 최근 16주
- 상세 기록: 최근 52주, 가로 스크롤

```text
          6월             7월             8월
월   □ □ ░ ▒ ▓ □ ░ ▒ ▓ █ □ ░ ▒
화   □ ░ ░ ▒ □ □ ▒ ▒ ▓ █ □ □ ░
수   □ □ ▒ ▒ ░ ░ ▓ ▒ ▓ █ ░ □ ▒
목   ░ □ ▒ ▓ ░ □ ▓ ▓ █ █ ▒ ░ ▒
금   □ ░ ▒ ▓ ▒ ░ ▓ █ █ █ ▒ ░ ▓
토   ░ ▒ ▓ █ ▒ ▒ █ █ █ █ ▓ ▒ █
일   □ ░ ▒ ▓ □ ▒ ▓ █ ▓ █ ▒ ░ ▓

적음  □ ░ ▒ ▓ █  많음
```

## 12.3 기본 지표 전환

상단 세그먼트 컨트롤을 둔다.

```text
[ 횟수 ] [ 누적 강도 ]
```

- 기본값: `횟수`
- 횟수: 해당 날짜의 완료 이벤트 수
- 누적 강도: 해당 날짜의 강도 합계

## 12.4 횟수 기준 농도

| 레벨 | 일일 완료 횟수 |
|---:|---:|
| 0 | 0회 |
| 1 | 1회 |
| 2 | 2회 |
| 3 | 3~4회 |
| 4 | 5~6회 |
| 5 | 7회 이상 |

## 12.5 누적 강도 기준 농도

| 레벨 | 일일 누적 강도 |
|---:|---:|
| 0 | 0 |
| 1 | 1~3 |
| 2 | 4~7 |
| 3 | 8~12 |
| 4 | 13~19 |
| 5 | 20 이상 |

초기 사용자 테스트 결과에 따라 임계값을 조정할 수 있으나, 기간마다 상대값으로 바꾸지 않고 고정 범위를 사용한다. 그래야 같은 농도가 언제나 같은 의미를 가진다.

## 12.6 셀 상세 정보

사용자가 셀을 탭하면 하단 시트를 표시한다.

```text
2026년 9월 4일
────────────────
총 4회
누적 강도 13
평균 강도 3.3

11:03  강도 4
15:26  강도 2
18:42  강도 3
22:18  강도 4
```

## 12.7 시각화 해석 원칙

진한 셀을 성공·우수·보상으로 표현하지 않는다. 실행 횟수가 많다는 것은 그날 앱을 많이 찾았다는 의미이지, 자기통제에 더 성공했다는 의미가 아니다.

따라서 다음 요소를 넣지 않는다.

- 횟수가 많을 때 축하 효과
- 연속 사용 스트릭을 목표로 강요하는 배지
- 다른 사용자와 순위 비교
- `오늘도 5회 채우기`와 같은 목표

권장 명칭:

- `사용 기록`
- `마음자로를 찾은 날`
- `일별 실행 밀도`

비권장 명칭:

- `성공 잔디`
- `참기 점수`
- `의지력 등급`

## 12.8 시간대 처리

이 앱은 식욕 패턴을 현지 생활 시간과 연결해야 하므로, 이벤트 발생 당시의 현지 날짜와 시간대를 함께 저장한다. 해외 이동 중 기록도 사용자가 경험한 현지 날짜에 표시한다.

표현 문구:

- 특정 시간대 기록이 많다고 질환 또는 식습관 문제를 진단

## 15.1 권장 구현 방식

### iOS와 Android 동시 개발 시

| 영역 | 권장 기술 |

| Android 공유 상태 | DataStore/Glance state |
| 차트 | CustomPainter 또는 경량 차트 라이브러리 |
| 햅틱 | 네이티브 플랫폼 채널 |
| 서버 | 없음 |

Flutter로 앱 본체를 만들더라도 홈 화면 위젯은 각 운영체제의 네이티브 프레임워크로 구현한다.

- Core Haptics
- Rive 또는 SwiftUI mask animation

1인 개발로 제품 가설을 먼저 검증한다면 iOS 우선 구현이 가장 단순하다.

# 17. 저작권·브랜드·앱 심사 기준

## 17.1 에셋 사용 원칙

이 프로젝트는 닥터나우 페이지의 파일이나 코드를 추출하지 않고 별도 에셋을 제작한다. `세로형 주사기 내부 액체가 감소하는 기능적 아이디어`를 참고하되, 구체적인 그래픽 표현은 독립적으로 제작한다.

### 사용 가능성이 높은 영역

- 세로형 가상 주사기
- 내부 액체 표시
- 화면을 누르면 액체가 감소하는 동작
- 햅틱과 완료 연출
- 강도 선택

### 독립 제작해야 하는 영역

- 주사기 비율과 외곽 형태
- 라벨·색상·폰트
- 액체 질감
- 화면 구성과 전환
- 문구
- 효과음과 햅틱 패턴

### 사용하지 않을 영역

- 닥터나우 원본 에셋·코드·영상
- 닥터나우 로고
- 실제 마운자로 또는 제약사 로고
- 실제 제품과 구별하기 어려운 펜 디자인
- 원문 카피의 그대로 사용

저작권은 일반적으로 아이디어 자체보다 구체적인 창작 표현을 보호하지만, 실제 침해 여부는 두 표현의 창작성과 실질적 유사성을 구체적으로 비교해 판단한다.

## 17.2 프로젝트명

`마음자로`는 현재 문서의 가칭이다. 공개 출시 전 다음을 별도로 확인한다.

1. KIPRIS에서 동일·유사 상표 검색
2. 닥터나우 공식 서비스와 혼동 가능성 검토
3. 앱스토어 이름·아이콘·스크린샷에서 공식 제휴로 오인될 요소 제거
4. 필요 시 독립 브랜드명으로 출시

공개 재사용을 허용하는 닥터나우의 공식 라이선스 문서는 확인되지 않았다.

## 17.3 스토어 심사 대응

### App Store

- 다른 앱의 이름이나 UI를 단순 모방한 copycat으로 보이지 않게 고유 브랜드·그래픽·기록 기능을 갖춘다.
- 단순 애니메이션 재생 앱이 아니라 위젯, 기록, 기여도 히트맵, 패턴 분석 등 지속적 효용을 제공한다.
- 실제 식욕 억제 또는 치료 효능을 주장하지 않는다.
- 건강 관련 데이터는 로컬에 저장하고 광고·마케팅 목적으로 사용하지 않는다.

### Google Play

- Health Apps Declaration을 정확하게 작성한다.
- 앱의 기능에 따라 `Nutrition and Weight Management` 또는 `Stress Management, Relaxation, Mental Acuity` 범주 적용 가능성을 검토한다.
- 공개 개인정보처리방침을 제공한다.
- 의료기기가 아니라는 점과 실제 의약품을 대체하지 않는다는 점을 명시한다.

## 17.4 권장 면책문구

23:59에 시작해 00:00에 완료한 경우 완료 시각의 현지 날짜로 기록한다.

# 21. QA 및 완료 기준

## 21.1 기능 테스트

- 강도 1~5가 위젯에서 모두 선택된다.
- 위젯에서 선택한 값이 앱에 정확히 전달된다.
- 강도별 액체 높이, 시간, 햅틱 횟수가 다르다.
- 터치를 놓으면 일시 정지된다.
- 완료 전에는 기록이 생기지 않는다.
- 완료 후 이벤트가 정확히 1건 생긴다.
- 대시보드와 위젯의 오늘 요약이 갱신된다.
- 히트맵의 날짜별 횟수와 누적 강도가 DB 집계와 일치한다.
- 앱 재시작과 기기 재부팅 후에도 기록이 유지된다.
- 네트워크가 없는 상태에서 전체 핵심 기능이 작동한다.

## 21.2 시각·모션 테스트

- 주사기 에셋이 다양한 화면 비율에서 잘리지 않는다.
- 액체 마스크가 60fps를 목표로 부드럽게 작동한다.
- 완료 전환 시 깜빡임이 없다.
- 다크모드와 라이트모드 모두 가독성이 확보된다.
- Reduce Motion 모드에서 대체 표현이 작동한다.

## 21.3 위젯 테스트

- 앱이 종료된 상태에서도 강도 변경 가능
- 강도 변경 후 콜드 스타트에서도 최신 값 사용
- 여러 위젯을 설치했을 때 상태 동기화
- OS 업데이트 및 기기 재부팅 후 위젯 복구
- iOS/Android의 주요 홈 화면 크기 대응

## 21.4 스토어 심사 체크

- 마운자로·제약사 로고 없음
- `mg`, 치료, 식욕 억제 효능 문구 없음
- 닥터나우 공식 앱으로 오인될 메타데이터 없음
- 개인정보처리방침 URL 유효
- 앱 지원 연락처 유효
- 건강 기능 선언 내용과 실제 기능 일치

# 25. 수익 모델

MVP는 무료 검증을 권장한다. 초기 사용자 반응이 확인되면 광고 없는 1회 구매 모델이 앱 성격에 적합하다.

### 무료

- 기본 주입 에셋 1종
- 강도 1~5
- 기본 위젯
- 최근 30일 기록
- 기본 문구 풀

### Pro 1회 구매

- 52주 기여도 히트맵
- 추가 주사기·액체 테마
- 전체 시간대·요일 분석
- 사용자 문구 추가
- CSV/JSON 내보내기
- 위젯별 강도 프리셋

건강 관련 사용 데이터를 광고 타기팅에 활용하지 않는다. 핵심 기능을 월 구독으로 잠그는 것보다, 시각 테마와 고급 기록 기능을 1회 구매로 제공하는 방식을 우선 검토한다.

# 26. 주요 위험과 대응

| 위험 | 영향 | 대응 |
|---|---|---|
| 닥터나우 copycat으로 보일 가능성 | 권리 분쟁·심사 반려 | 독립 에셋·브랜드·기록 기능, 원본 자산 미사용 |
| 의료 앱으로 오인 | 심사 강화·사용자 오해 | mg 제거, 비의료 면책, 효능 주장 금지 |
| 앱이 너무 단순해 보임 | App Store 최소 기능 반려 | 위젯·기록·히트맵·패턴 분석을 완성도 있게 제공 |
| 높은 사용 횟수의 게임화 | 불필요한 반복 사용 유도 | 횟수를 성공 점수로 표현하지 않음 |
| 위젯 상태 지연 | 잘못된 강도로 실행 | 공유 저장소를 source of truth로 사용 |
| Android 햅틱 편차 | 주입감 불일치 | 기기별 fallback과 강도 보정 |
| 실제 참기 성과 오해 | 데이터 신뢰 저하 | 성공률·식욕 감소율 미표시 |
| `마음자로` 명칭 | 출처 혼동·상표 문제 | 출시 전 상표·혼동 검토, 필요 시 독립 이름 |

# 27. 최종 확정안

## 제품 핵심 흐름

```text
위젯에서 강도 1~5 설정
        ↓
주입 버튼 한 번 탭
        ↓
주사기 화면 즉시 표시
        ↓
“스마트폰을 배에 대고 마음자로를 길게 눌러주세요”
        ↓
누르는 동안 선택 강도만큼 액체 감소 + 햅틱
        ↓
“강도 N 주입 완료”
        ↓
강도에 맞는 마인드 컨트롤 문구
        ↓
시간·강도 자동 기록
        ↓
일별 기여도형 히트맵과 시간대 패턴에 반영
```

## MVP의 핵심 차별점

1. 위젯에서 바로 시작하는 1차 인터페이스
2. 별도 제작한 고품질 주사기·액체 애니메이션
3. 강도 1~5에 따라 달라지는 액체량·햅틱·문구 톤
4. 몇 초 안에 끝나는 입력 없는 자기조절 의식
5. GitHub Contribution 형태의 장기 실행 기록
6. 시간대·요일별 사용 패턴 분석
7. 로컬 전용 데이터와 광고 없는 구조

## 개발 우선순위

```text
주입감 완성도
   > 위젯 진입 속도
   > 기록 정확성
   > 기여도형 시각화
   > 추가 기능
```

이 앱은 기능 수가 아니라 **위젯을 누른 뒤 몇 초 동안 느끼는 시각적·촉각적 완성도와 반복 가능한 행동 루프**가 품질을 결정한다.
